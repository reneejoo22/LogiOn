# 보드 음성 처리 검증 (STT·LLM·TTS 모두 보드) — 2026-11-20

폰 대신 PC 에서 시연 녹음 5개를 보드 `POST /api/assistant/voice` 로 보냈다. 보드가 STT → 파이프라인(LLM, NPU) → TTS 를 모두 처리한다.

- 보드: Orange Pi 5 Plus (RK3588, 8코어, 16GB). CPU/NPU 클럭은 고정하지 않았다.
- STT: SenseVoice-Small int8, CPU 4스레드. TTS: VITS kss_low, CPU 2스레드. VAD: silero. sherpa-onnx 1.13.8.
- LLM: `logion-delivery_w8a8_opt1_cal450.rkllm` (NPU).
- 입력: 연구실 PC 의 m4a 녹음을 ffmpeg 로 wav 16kHz mono 로 바꿈.
- 연결: PC → 보드 Tailscale. 한 세션에서 순서대로 보냈다.
- DB: 원본 `backend/data/logion.db` 의 복사본(`logs/logion_voice_20261120b.db`). 원본은 그대로다.
- 스크립트: [`scripts/board/voice_test_recordings.py`](../../scripts/board/voice_test_recordings.py)
- 원자료: `results_run2.json` (아래 표), `results_run3.json` (다시 잰 것), `results_run1_before_fix.json` (파이프라인 수정 전)

단위는 ms. 표의 열은 다음과 같다.

- **LLM:** 파이프라인 전체(LLM + 값 보정 + DB 기록)다.
- **TTS:** 응답 전체를 wav 로 만든 시간이다.
- **PC 에서 잰 왕복:** 업로드부터 JSON 응답까지다. 응답 wav 내려받기는 추가로 10~25ms 걸렸다.

**다시 잰 결과(run3):** 서버 전체 1,885 / 2,488 / 3,095 / 3,483 / 1,349 ms 로, 위와 2% 안쪽 차이였다.

**응답 음성:** [`audio/`](audio/) 에 있다 (22.05kHz mono wav, 2.8~5.9초).

**4번:** "점장님" 을 "정자님" 으로 잘못 들었다. 폰 STT(11-17 시연)도 같은 오인식이었다. 같은 모델이고 녹음도 같다.

## 수정 전 결과 (run1)와 고친 것

처음 돌렸을 때 4번과 5번이 실패했다.

- **4번:** LLM 이 `complete` 에 `item="장점"` 을 같이 넣었다. 파이프라인이 그 값을 품목으로 찾다가 "'장점'이라는 품목을 찾지 못했어요." 하고 되물었다.
- **5번:** 그 되묻기가 남아 있어서, 다음 말 "근처 화장실 어디야?" 를 품목 답으로 삼켰다.

고친 것과 확인:

- `demo/pipeline.py` 의 `resolve()` 가 기능에 없는 값을 버리게 했다. `complete` 는 store·receiver 만 쓴다.
- 테스트를 추가했다: `test_value_outside_function_is_ignored`.
- 다시 돌린 결과가 위 표다.

폰 STT 는 같은 녹음을 "성수영무 장 납품완 …" 으로 들어서, 11-17 시연 때는 이 문제가 드러나지 않았다.

## 폰 STT·TTS(11-17 시연) 와 비교

| | 폰에서 STT·TTS (에뮬레이터, PC CPU) | 보드에서 STT·TTS |
|---|---|---|
| STT | 332~732 ms | **180~349 ms** |
| LLM (파이프라인) | 591~1,991 ms | 528~1,940 ms (같은 보드 NPU) |
| TTS | 첫 문장 238~422 ms 뒤 재생 시작 (문장별 생성하며 재생) | 응답 전체 567~1,228 ms 뒤 재생 시작 (wav 한 번에) |

- 보드 STT 가 더 빨랐다. 폰 쪽은 실제 폰이 아니라 PC 의 에뮬레이터라서, 실제 폰과의 비교는 아니다.
- TTS 는 첫 소리가 0.3~0.8초 늦어졌다. 보드는 응답 전체를 만든 뒤 보내기 때문이다.
  - 응답이 대부분 한 문장이라 차이는 문장 길이만큼이다.
  - 줄이려면 첫 문장만 먼저 만들어 보내는 방법이 있다 (스트리밍, 다음 작업 후보).
