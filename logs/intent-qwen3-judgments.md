# intent-qwen3 작업 중 판단 기록 (2026-10-29)

- 시스템 지시문은 `intent_qwen_common.INTENT_SYSTEM` 한 곳에 두고 학습·평가·캘리브레이션이 모두 import (바꾸면 재학습 필요).
- 라벨은 영어 함수명 그대로 사용. 첫 토큰이 6개 모두 달라 확률 추출 가능해 별도 라벨 단어를 만들지 않았다.
- 학습 설정은 FC 학습과 같은 LoRA(r16/alpha32)와 lr 2e-4, 3 epoch. 데이터/하이퍼파라미터 탐색 없음 (결과가 낮아도 기준·분할 변경 금지 지시).
- 체크포인트는 val 탐욕 정확도로만 선택(epoch 2). test 는 병합 모델 하나로 1회.
- RKLLM 이 로짓을 주는지 몰라서 평가를 'argmax 전용' 과 '확률 사용(PC 전용)' 으로 분리 보고. argmax 전용 시뮬레이션은 one-hot 확률(되묻기 불가).
- 파이프라인 교체 평가에서 tau/건너뛰기 선택은 v2.1 과 같은 규칙(val). 확률 모드의 선택값이 tau 격자 상한(0.5)이라 가장자리임을 표시만 하고 격자를 넓히지 않았다.
- 캘리브레이션은 train 몫 템플릿으로 새 시드 생성, 모든 split 문장과 중복 제거, target 은 병합 모델 출력. ask/hard 유형이 안 만들어지는 기능은 clear 로 보충해 함수별 80 유지.
- docker/rkllm-toolkit 이 없어 RKLLM 변환은 하지 않고 문서화만 했다. 보드 지연은 벤치마크 기반 추정으로 표시.
- 학습 중 reserved VRAM 이 7.98 GB 로 컸지만 step 시간이 안정적(1.17 s)이라 계속 진행.
