# 백엔드 작업 노트 — 음성 비서 연결

브랜치: `backend-assistant-chat` (2026-10-24, 아직 커밋 전)

---

## 1. 무엇을 했나

**AI 파이프라인을 백엔드에 붙였습니다.** 전에는 AI(`demo/pipeline.py`)가 seed 복사본(메모리)으로만 돌아서, "완료로 기록했어요" 라고 답해도 실제 DB 는 그대로였습니다.

```
전:  앱 ──✗──  AI(데모 서버, 메모리 목업)  ──✗──  백엔드 ── DB
지금: 앱 ──✗──  백엔드 /api/assistant/chat ── AI 파이프라인 ── delivery.py ── DB
      └ 아직 (ChatScreen.kt 가 서버를 안 부름)
```

| 파일 | 내용 |
| --- | --- |
| `app/services/assistant.py` (새 파일) | `pipeline.Assistant` 를 상속한 `DbAssistant`. 점포·품목·오늘 배송지를 **DB 에서 읽고**, 납품 완료·이상 보고는 화면 API 와 같은 `delivery.py` 함수로 **DB 에 기록** (`source: "voice"`). 되묻기 상태는 `session_id` 별로 따로 보관하고 3분 지나면 버림. 말한 문장은 `utterance_logs` 에 남김 |
| `app/api/assistant.py` (새 파일) | `POST /api/assistant/chat`, `GET /api/assistant/status` |
| `app/main.py` | 서버 켤 때 모델을 한 번 올림. 실패하면 음성 API 만 503, 화면 API 는 그대로 |
| `tests/conftest.py`, `tests/test_assistant.py` (새 파일) | 가짜 모델로 DB 연결 확인 10개. 전체 20개 통과 |
| `README.md` | API 표, 음성 비서 설명 추가 |
| `../demo/pipeline.py` (AI 쪽, 2줄) | 버그 수정. 아래 1-1 참고 |

AI 로직(의도분류, 갈림길, 값 보정, 응답 문장)은 **새로 짜지 않고 `pipeline.py` 를 그대로 씁니다.** AI 쪽이 고치면 백엔드에도 그대로 반영됩니다.

추가로 넣은 안전장치:
- LLM 이 DB 에 없는 문제 유형(예: `"이상함"`)을 내면 저장하지 않고 "어떤 문제인가요?" 라고 되물음 (안 하면 DB CHECK 에 걸려 500)
- 수량이 `"2"` 처럼 문자열이면 숫자로 바꾸고, 0 이하이면 버림

응답 형식은 `docs/backend_integration.md` 4장(요청·응답)과 6장(앱 처리)을 따릅니다.

### 1-1. AI 파이프라인에서 고친 버그 (AI 담당자에게 공유 필요)

품목 후보가 여러 개일 때 되묻고("참치삼각김밥, 스팸마요삼각김밥 중 어떤 건가요?"), 그 답을 받으면 **품목이 아니라 점포 칸에 넣어서** "'참치삼각김밥'이라는 점포를 찾지 못했어요" 로 끝났습니다.
원인은 `run()` 이 질문 문장에 "품목" 이라는 글자가 있는지로 빠진 칸을 짐작했기 때문입니다. `resolve()` 가 빠진 칸(`_missing="item"`)을 직접 알려 주도록 고쳤습니다. 채팅 데모(`demo/chat_server.py`)에도 같은 버그가 있었습니다.

## 2. 점포 매칭 문제

### 2-1. 현황

| | 점포 |
| --- | --- |
| AI 학습 데이터 | 역삼점, 서초점, 방배점, 개포점, 신림점, 잠실점 … (24곳) |
| DB (`app/db/seed.py`) | GS25 성수연무장점, CU 서울숲점, 세븐일레븐 뚝섬점 (3곳) |

### 2-2. 일부러 넣은 것인가?

**점포 이름이 다른 것 자체는 의도된 게 아닌 것으로 보입니다.** 문서들은 이 문제를 미해결로 적고 있습니다.
- `DB_DESIGN.md` 226줄: "시연용 점포를 한쪽으로 통일 … 확인 필요"
- `docs/1st_report_summary.md` 149줄: 한계 목록에 "점포 이름이 DB 와 다름"
- `docs/backend_integration.md` 3-3: "지금 상태로는 안 맞습니다", 해결 방법 3가지 제시

**반면 "못 찾으면 지어내지 않는다" 는 의도된 설계입니다.** (`README.md` 48줄 "모델이 없는 값을 지어내지 않게", 연결 가이드 3-3 "못 찾았을 때 지어내지 마세요")
그래서 **DB 에 없는 점포를 말했을 때 실행하지 않고 되묻는지** 를 확인하는 용도로는 지금 상태가 쓸모 있습니다. 아래에서 확인했습니다.

### 2-3. 확인 결과 (가짜 모델로 DB 에 붙여 실행)

LLM 출력은 정해 두고, 그 뒤 값 보정·되묻기·DB 기록만 실제 코드로 돌렸습니다.

| # | 말 | 응답 | 판정 |
| --- | --- | --- | --- |
| A | 역삼점 뭐 내려 / 역삼점 우유 두 개 터졌어 / 역삼점 납품 완료 | "'역삼점'이라는 점포를 찾지 못했어요." (실행 안 함, DB 그대로) | ✅ 지어내지 않음 |
| B1 | 서울숲 뭐 내려 | CU 서울숲점 납품은 … | ✅ 포함 매칭 |
| B2 | 성수점 뭐 내려 | GS25 성수연무장점 납품은 … | ⚠️ 발음 유사도(0.67 ≥ 0.6)로 매칭. 의도한 거면 OK, 아니면 기준이 느슨함 |
| E | 역삼점 뭐 내려 → **서울숲점** | CU 서울숲점 납품은 … | ✅ 되묻기 답을 받아 이어서 처리 |
| F | 역삼점 우유 두 개 터졌어 → **성수연무장점** | GS25 성수연무장점 서울우유 2개 파손으로 기록했어요. (DB 에 기록됨) | ✅ |
| C | 역삼점 뭐 내려 → **다음 어디야** | "'다음 어디야'이라는 점포를 찾지 못했어요." | ❌ 버그 |
| D | 역삼점 뭐 내려 → **콜라 몇 박스야** | "'콜라 몇 박스야'이라는 점포를 찾지 못했어요." | ❌ 버그 |

### 2-4. 발견한 문제

1. **못 찾은 뒤에 한 다른 말을 점포 이름으로 받아 버립니다 (C, D).**
   점포를 못 찾으면 안 보이는 "점포 되묻기" 상태가 남습니다. 그 뒤 12글자 이하의 말은 무조건 점포 답으로 처리됩니다(`pipeline.py` `run()` 의 `not cands and len(text) <= 12`). 그래서 기사가 마음을 바꿔 다른 걸 물어도 계속 "점포를 찾지 못했어요" 만 나옵니다. 12글자를 넘는 말을 하거나 3분이 지나야 풀립니다.
   연결 가이드 3-5 "맞는 것이 없으면 새로운 문장으로 보고 처음부터 처리" 와 다릅니다.
2. **질문이 아니라 안내문입니다.** "찾지 못했어요" 로 끝나서 기사는 점포를 다시 말하라는 건지 알 수 없습니다. `options` 도 `null` 이라 앱이 버튼을 띄울 수 없습니다. 그런데 `ask` 는 채워져 있어서 앱은 "답을 기다리는 중" 으로 표시하게 됩니다.
3. **조사 오류.** "'다음 어디야'**이라는**" 처럼 받침이 없어도 "이라는" 이 붙습니다 (`josa()` 를 안 씀). 품목 쪽 문구도 같습니다.

### 2-5. 고치는 방법 제안 (아직 안 고침)

- 못 찾았을 때 **오늘 배송지 점포를 선택지로** 줍니다.
  "'역삼점'은 오늘 배송지에 없어요. 성수연무장점, 서울숲점, 뚝섬점 중 어디인가요?" + `options=[…3곳]`
  → 2번이 해결되고, 후보가 생기므로 1번도 함께 풀립니다(후보와 안 맞는 말은 새 문장으로 처리하는 기존 규칙을 탐).
- 위가 과하면 최소한 1번만이라도: 점포 되묻기 답은 **DB 점포와 매칭될 때만** 받고, 아니면 새 문장으로 처리합니다.
- 이 수정은 `pipeline.py` (AI 쪽) 를 고치는 게 맞습니다. 백엔드에서 덮어쓰면 데모와 동작이 달라집니다. AI 담당자와 정한 뒤 작업합니다.
- 점포 이름 자체를 맞추는 것(seed 를 학습 점포로 바꾸거나 재학습)은 연결 가이드 3-3 의 3가지 중에서 팀이 정합니다.

## 3. 모델 학습이 끝나면 할 일

지금 `notebooks/LogiOn_AI_pipeline.ipynb` 로 학습 중입니다 (약 40분). 끝나면 `out/intent_model`, `out/fc_merged` 가 생깁니다.

1. 서버 켜기 (torch 가 있는 저장소 `.venv` 에 백엔드 패키지도 설치해 둠)
   ```powershell
   cd backend
   ..\.venv\Scripts\python -m uvicorn app.main:app --host 0.0.0.0 --port 8000
   ```
   로그에 "음성 비서 준비됨 (GPU 이름)" 이 나와야 합니다. 모델 로딩에 수십 초가 걸립니다.
2. `GET http://localhost:8000/api/assistant/status` → `"ready": true`
3. http://localhost:8000/docs 에서 `POST /api/assistant/chat` 으로 직접 확인
   - [ ] `다음 어디야` → 다음 배송지, `action: refresh_route`
   - [ ] `여기 뭐 내려` → 다음 배송지 품목
   - [ ] `우유 두 개 터졌어` → `GET /api/stops/1` 의 `issues` 에 `source: "voice"` 로 생김
   - [ ] `삼각김밥 터졌어` → 후보 2개 되묻기 → `참치삼각김밥` 답 → 기록됨 (1-1 버그 수정 확인)
   - [ ] `점장님한테 넘겼어` → 배송지 `done`, 앱 홈 화면에도 반영
   - [ ] **실제 모델이 `역삼점` 을 `store` 로 뽑는지**, 그리고 2-3 의 A·C·D 가 똑같이 나오는지
   - [ ] 응답 속도(`latency_ms`) — 연결 전 데모 기준 LLM 문장 0.2~3초
4. 결과에 따라 2-5 수정 여부 결정
5. 그다음: 앱 `ChatScreen.kt` 연결 (`LogiOnApi.kt` 에 chat 추가, `docs/backend_integration.md` 6장)
